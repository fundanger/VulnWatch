CVE Emailer v2

Automated CVE monitoring, enrichment, and multi-channel alerting

CVE Emailer continuously queries the NIST NVD API for CVEs matching your keywords, enriches each result with EPSS exploit-probability scores and CISA KEV (Known Exploited Vulnerabilities) flags, stores them in a local SQLite or Postgres database, and dispatches alerts via email, Slack, webhooks, Jira, or ServiceNow.

It ships with a full-screen Terminal UI for interactive use and a Flask REST API + web dashboard for production deployment.

New to the tool? Jump to Quick Start to be up and running in under 5 minutes.

Quick Start

Option A — Interactive TUI

# 1. Install dependencies
pip install -r requirements.txt

# 2. Launch the terminal UI (setup wizard runs automatically on first start)
python main.py

The setup wizard prompts for your email credentials, NVD API key, and initial keywords. All settings are stored in config.ini in the same directory.

Option B — Docker (recommended for production)

# 1. Copy the example env file and fill in your values
cp .env.example .env

# 2. Start all services (Postgres + API server + headless scanner)
docker compose up -d

# 3. Open the dashboard
# http://localhost:5000

Option C — Headless / scheduled

# Install a background job for this OS (cron / launchd / Task Scheduler)
python scheduler.py install

# Run a single scan cycle manually
python scheduler.py run

# Check job status
python scheduler.py status

# Remove the job
python scheduler.py remove

Architecture

NVD API ──────► search.py ──────► database.py (SQLite / Postgres) │ epss.py ◄─┤ EPSS + CISA KEV enrichment │ ▼ mail.py email alerts notify.py Slack / webhook integrations.py Jira / ServiceNow tickets tui.py terminal UI (interactive) api.py Flask REST API + web dashboard scheduler.py cross-platform background job installer logger.py structured JSON logging (SIEM-compatible)

Each scan cycle calls search.run_once(), which reloads config.ini fresh so settings changes take effect without a restart. Keywords are processed in parallel; NVD results are paginated (2 000 CVEs/page). New and severity-upgraded CVEs are enriched, written to the database, and dispatched.

In digest mode, CVEs are queued in the digest_queue table and batched into a single email on your chosen schedule (hourly / daily / weekly).

Keywords & Severity Overrides

Keywords are stored as a newline-separated list under [DEFAULT] keywords. Each keyword is used as an NVD full-text search term. Results are stored in a dedicated SQLite/Postgres table named after the keyword (non-word characters replaced with _).

You can append a severity override using the ::SEVERITY syntax to set a different minimum alert threshold per keyword: 

keywords =
    Apache Knox
    log4j::CRITICAL
    OpenSSL::MEDIUM
    VMware ESXi

In this example, log4j only alerts on CRITICAL CVEs while OpenSSL alerts on MEDIUM and above. Keywords without a suffix use the global minSeverity setting.

Valid severity levels (ascending): NONE → LOW → MEDIUM → HIGH → CRITICAL

Notification Profiles

Profiles let you run isolated scans with different keywords, severity thresholds, and recipient lists. When one or more profiles exist, the scheduler runs run_profiles() instead of run_once().

Profiles are managed via the TUI (p) or the REST API.

FieldDescription
nameUnique profile identifier.
keywordsNewline-separated keywords (overrides global list).
min_severityMinimum severity to alert on.
recipientsComma-separated email addresses for this profile.
webhook_urlWebhook URL for this profile (optional).
slack_webhookSlack webhook for this profile (optional).
digest_mode0 = immediate alerts, 1 = batched digest.
digest_schedulehourly / daily / weekly.

Digest Mode

When digest mode is enabled, found CVEs are queued in the digest_queue table instead of dispatched immediately. After each scan cycle, the scheduler checks whether the configured interval has elapsed since the last digest was sent. If so, it batches all queued CVEs into a single email and marks them sent.

Integrations

Email (Gmail)

Alerts are sent via SMTP (default: smtp.gmail.com:587 with STARTTLS). Generate a Gmail App Password at myaccount.google.com → Security → 2-Step Verification → App passwords — your account password will not work.

Slack

Create an Incoming Webhook in your Slack workspace and set CVE_SLACK_WEBHOOK (or slackWebhook in config.ini). Each alert posts a plain-text message with CVE ID, severity, CVSS score, and description.

Generic Webhook

Set CVE_WEBHOOK_URL to POST a JSON payload for each alert batch to any HTTP endpoint (e.g. Zapier, n8n, SIEM ingest). Payload structure: 

{
  "cves": [
    {
      "cve_id":      "CVE-2024-12345",
      "severity":    "CRITICAL",
      "cvss_score":  9.8,
      "epss_score":  0.94,
      "kev":         true,
      "description": "..."
    }
  ]
}

CVE Enrichment

Every CVE is enriched before being written to the database:

  • EPSS (Exploit Prediction Scoring System) — probability (0–1) that a CVE will be exploited in the wild within the next 30 days, sourced from api.first.org. Batched 30 IDs per request.
  • CISA KEV — the CISA Known Exploited Vulnerabilities catalog (cisa.gov). Cached in memory for 1 hour. CVEs in this list are flagged with a KEV badge in the dashboard and alerts.
  • CVSS score and vector — sourced directly from NVD.
  • CWE / CPE — weakness category and platform affected, from NVD.
  • References — advisory URLs from the NVD record, stored as JSON.

A CVE is re-alerted if its severity category improves (e.g. HIGH → CRITICAL) or its CVSS score increases by ≥ 1.0 since the last alert. The previous alerted severity and score are tracked in the database.

Database

CVE Emailer uses SQLAlchemy Core and supports both SQLite (default) and PostgreSQL. The database is resolved from the DATABASE_URL environment variable; if unset it defaults to sqlite:///cve_emailer.db in the script directory.

System tables

TablePurpose
scan_historyOne row per scan cycle: timestamps, new/updated CVE counts, error.
notification_profilesNamed alert profiles with keywords, severity, recipients, digest settings.
digest_queuePending CVEs for digest-mode profiles; sent_at written when dispatched.

CVE tables

Each keyword gets its own table named after the keyword (non-word characters replaced with _). The primary key is the full CVE ID string (e.g. CVE-2024-12345). Table names are double-quoted in all queries to support keywords with spaces or hyphens.

New columns are added via ALTER TABLE ... ADD COLUMN inside try/except blocks, so upgrading an existing database is safe — just restart the app.

Environment Scanners

Run a scanner on any machine you want to monitor. Each script fingerprints installed software, running services, OS/kernel, listening ports, and package-manager libraries, then either prints a keyword list or uploads it directly to CVE Emailer — creating or updating an Asset record so CVEs are automatically correlated to the host.

All three scanners require no root / admin rights (most checks), support --append mode to merge into the existing keyword list, and filter generic port-only names and unknown Docker image names to avoid NVD noise.

Python — scan_environment.py

Cross-platform (Windows / Linux / macOS). Recommended when Python 3.10+ is available.

# Print keyword list to stdout
python scan_environment.py

# Full JSON inventory
python scan_environment.py --json

# Upload to dashboard + create/update asset
python scan_environment.py --upload http://your-dashboard:5000 --token YOUR_API_SECRET \
    --asset-name PROD-WEB-01 --environment production \
    --owner infra-team --append

# Write keyword list to file
python scan_environment.py --out keywords.txt
FlagDescription
--upload URLBase URL of a running CVE Emailer dashboard.
--token SECRETAPI_SECRET bearer token for authenticated upload.
--asset-name NAMEAsset name in the inventory (default: hostname).
--environment ENVproduction / staging / development / dmz
--owner TEAMOwner/team name stored against the asset.
--asset-tags TAGSExtra comma-separated tags to attach to the asset.
--appendMerge into existing keywords; scanner wins on version conflicts.
--jsonOutput full JSON inventory instead of keyword list.
--out FILEWrite output to file instead of stdout.

Bash — scan_environment.sh

Linux and macOS. No Python required — pure bash with curl for uploads.

chmod +x scan_environment.sh

# Print keyword list
./scan_environment.sh

# Upload to dashboard + create/update asset
./scan_environment.sh --upload http://your-dashboard:5000 --token YOUR_API_SECRET \
    --asset-name PROD-LNX-01 --environment production --append

# Preview what would be uploaded (no changes made)
./scan_environment.sh --upload http://your-dashboard:5000 --token SECRET --dry-run

Accepts the same flags as the Python script (--upload, --token, --asset-name, --environment, --owner, --asset-tags, --append, --dry-run, --json, --out).

PowerShell — Scan-Environment.ps1

Windows only. No external dependencies — uses WMI, .NET APIs, and the Windows registry.

# Print keyword list
.\Scan-Environment.ps1

# Upload to dashboard + create/update asset
.\Scan-Environment.ps1 -DashboardUrl http://your-dashboard:5000 -Token YOUR_API_SECRET `
    -AssetName PROD-WIN-01 -Environment production -Owner infra-team -Append

# Preview what would be uploaded
.\Scan-Environment.ps1 -DashboardUrl http://your-dashboard:5000 -Token SECRET -DryRun

# Write JSON inventory to file
.\Scan-Environment.ps1 -Json -OutFile C:\temp\inventory.json
On Windows Server SKUs, the scanner also queries installed Windows Features (IIS, DNS, DHCP, ADCS, ADFS, Hyper-V, RDS) via Get-WindowsFeature. On workstation SKUs this section is silently skipped.

Keyword format produced

Each discovered product becomes one keyword with a ::SEVERITY override, trimmed to major.minor version for broader NVD hits: 

nginx 1.24::CRITICAL
PostgreSQL 16.1::CRITICAL
OpenSSH 9.3::HIGH
Python 3.11::MEDIUM
Docker 24.0::HIGH

Generic names (HTTP server, HTTPS server, SMTP server, etc.) are filtered out. Unknown Docker image names are silently dropped — only names in the built-in product whitelist produce keywords.
